## 3. UHF 物理チャンネルと中心周波数

### 3.1 実装されている式

`src/session.rs` の実装:

```text
ch 13..=62
center_hz = 473_142_857 + 6_000_000 * (ch - 13)
```

代表値（`tests/query_and_version.rs` で検証済み）:

| ch | 中心周波数 (Hz) | (MHz) |
| --- | --- | --- |
| 13 | 473,142,857 | 473.142857 |
| 14 | 479,142,857 | 479.142857 |
| 19 | 509,142,857 | 509.142857 |
| 52 | 707,142,857 | 707.142857 |
| 62 | 767,142,857 | 767.142857 |

473.142857 MHz は 6 MHz 間隔の基準値で、複数の二次情報（例: isdb-t.com の周波数表、
`[検索]`）で一致します。ARIB STD-B31 自体は**チャンネル中心周波数の式を規定せず**
（同規格は伝送方式を規定し、周波数配置は運用/制度側）、この式の最終根拠は国内割当
（S10。本文未取得）です。したがって中心周波数式は `[導出]` 相当で、規格本文の
`[本文確認]` 項目ではありません。

### 3.2 歴史的範囲 `13..62` と現行範囲 `13..52` の相違

- アナログ・デジタル併存期は UHF **ch 13–62** がデジタルテレビに割当てられて
  いました（S9: 「UHF channels 13 through 62 (470 - 770 MHz) have been assigned」）。
- 2011-07-25 のアナログ終了後、周波数再編（repacking）により **ch 53–62 を
  2012-07-25 までに明け渡し、ch 13–52 を使用**することになりました
  （S8: 「digital broadcasting needed to vacate channels 53-62 and use only
  channels 13 to 52 after 25 July 2012」）。
- したがって:
  - 歴史的 / 法制度上の割当は `13..62`
  - **現行の国内運用は `13..52`**

現状の実装は `13..=62` を受理します（`UHF_MIN_CHANNEL = 13`,
`UHF_MAX_CHANNEL = 62`）。このため ch 53–62 は現在は電波が出ておらず、
チューニングしても受信できない可能性が高いです。

**互換性の方針（変更しない）:** 現行実装の `13..=62` 受理は**後方互換のため維持**し、
本メモの作業では範囲を変更しません。`README.md` の `/stream` 状態コード表に
「現状は `13..=62` を受理」と明示し、歴史的範囲と現行 `13..52` の相違を併記して
います。受理範囲を狭めるか歴史的範囲を残すかの設計判断は**未解決の残課題**であり、
事実の整理にとどめ、コードは変更していません。

## 4. ワンセグ（部分受信）とチャネル符号化（§3.3–3.15、`[本文確認]`）

> 以下は ARIB STD-B31 v2.2-E1 の §3.3–3.15 および Table 3-1〜3-31 から転記した
> 値です。出典は表ごとに付記します。印刷ページ N = PDF ページ N+10。

### 4.1 方式の骨格

- ISDB-T は 1 チャンネル（6 MHz）を **13 の OFDM セグメント**に分割し、各セグメントは
  チャンネル帯域の 1/14（`Bws = 6000/14 = 428.571… kHz`）です（Table 3-1）。
- **部分受信（ワンセグ）は中央（segment No. 0）の 1 セグメント**のみを受信します。
  部分受信用のセグメント位置は**常に No. 0** でなければなりません（§3.14）。
  セグメント No. 0 は 13 セグメントの中心に配置され、その上下に No. 1,2,… が
  交互に並びます（§3.14、Fig. 3-32）。
- 階層は最大 3（layer A/B/C）。No. 0 を部分受信に使う場合、layer A をそこへ割当てます
  （§3.15.6.4）。
- 国際的には System C（BT.1306, S5）および移動体向け System F（BT.2016, S7）に
  相当します（二次確認。本文パラメータの突き合わせは未実施）。

### 4.2 Mode / GI / 主要数値（Table 3-1, Table 3-2）

Mode はキャリア間隔で決まります（§2.3）:

| 項目 | Mode 1 | Mode 2 | Mode 3 |
| --- | --- | --- | --- |
| キャリア間隔 `Cs` | `Bws/108` = 3.968… kHz | `Bws/216` = 1.984… kHz | `Bws/432` = 0.992… kHz |
| FFT サンプル数 | 2048 | 4096 | 8192 |
| 有効シンボル長 | 252 µs | 504 µs | 1008 µs |
| 1 フレームのシンボル数 | 204 | 204 | 204 |
| FFT サンプリング周波数 | `2048/252 = 8.126984… MHz` | 同左 | 同左 |
| 13 セグメント総キャリア数 | `108×13+1 = 1405` | `216×13+1 = 2809` | `432×13+1 = 5617` |
| 全帯域幅 `Bw = Bws·Ns + Cs` | ≈ 5.575 MHz | ≈ 5.573 MHz | ≈ 5.572 MHz |

ガードインターバル比とシンボル/フレーム長（Table 3-1 / 3-2）:

| GI 比 | GI 長 (Mode 1/2/3) | シンボル長 (Mode 1/2/3) | フレーム長 (Mode 1/2/3) |
| --- | --- | --- | --- |
| 1/4 | 63 / 126 / 252 µs | 315 / 630 / 1260 µs | 64.26 / 128.52 / 257.04 ms |
| 1/8 | 31.5 / 63 / 126 µs | 283.5 / 567 / 1134 µs | 57.834 / 115.668 / 231.336 ms |
| 1/16 | 15.75 / 31.5 / 63 µs | 267.75 / 535.5 / 1071 µs | 54.621 / 109.242 / 218.484 ms |
| 1/32 | 7.875 / 15.75 / 31.5 µs | 259.875 / 519.75 / 1039.5 µs | 53.0145 / 106.029 / 212.058 ms |

> 注: シンボル長 = 有効シンボル長 + GI 長。有効シンボル長は Mode 1/2/3 で
> 252/504/1008 µs（Table 3-1）。

### 4.3 セグメント内キャリア構成（Table 3-1）

1 セグメント（Mode 1/2/3 の順に 108/216/432 キャリア）の内訳:

| 種別 | 同期（コヒーレント）変調 | 差動変調 |
| --- | --- | --- |
| Data | 96 / 192 / 384 | 96 / 192 / 384 |
| SP (Scattered Pilot) | 9 / 18 / 36 | 0 / 0 / 0 |
| CP (Continual Pilot) | 0 / 0 / 0 | 1 / 1 / 1 |
| TMCC | 1 / 2 / 4 | 5 / 10 / 20 |
| AC1 | 2 / 4 / 8 | 2 / 4 / 8 |
| AC2 | 0 / 0 / 0 | 4 / 9 / 19 |

- 変調方式: 同期 = QPSK / 16QAM / 64QAM、差動 = DQPSK（Table 3-1）。
- 13 セグメント合計の TMCC キャリア数は `ns + 5·nd`（Mode 1）、
  `2ns + 10·nd`（Mode 2）、`4ns + 20·nd`（Mode 3）。`ns`/`nd` は同期/差動の
  セグメント数（Table 3-2）。
- CP は各セグメントの先頭キャリア（carrier 0）に加え、全帯域の右端に 1 本
  （Table 3-2 の `nd+1`）。
- **中央セグメント（No. 0）が同期か差動かは TMCC の segment type で決まります**。
  本メモは一方に決め打ちしません。

### 4.4 送信側チャネル符号化の順序（§3.1、Fig. 3-2）と各段の値

原典 Fig. 3-2（印刷 p.17–18）の送信順序:

```text
TS re-multiplex
  -> outer code RS(204,188)
  -> division into hierarchical layers
  -> byte -> bits (MSB first)
  -> energy dispersal
  -> delay adjustment
  -> bits -> byte (MSB first)
  -> byte interleaving
  -> byte -> bits (MSB first)
  -> convolutional (inner) coding
  -> bit interleaving / mapping
  -> combining of hierarchical layers
  -> time interleaving
  -> frequency interleaving (intra-segment; inter-segment within same modulation group)
  -> OFDM-frame structure (SP/CP/TMCC/AC)
  -> IFFT
  -> guard-interval insertion
```

各段の規格値:

- **Outer code (§3.3、Ordinance Annexed Table 12, Item 1):** shortened **RS(204,188)**。
  188 byte の先頭に 51 byte の `00HEX` を付けて (255,239) で符号化し、その 51 byte を
  除いたもの。GF(2^8)、原始多項式 `p(x) = x^8 + x^4 + x^3 + x^2 + 1`、
  生成多項式 `g(x) = (x-λ^0)(x-λ^1)…(x-λ^15)`、`λ = 02HEX`。
  204 byte 中 **最大 8 byte** のランダム誤りを訂正。パリティは 16 byte。
  誤り保護後の 204 byte を **transmission TSP** と呼ぶ。
- **Division of TS into hierarchical layers (§3.4):** 204 byte 単位（同期 byte の次から
  次の同期 byte まで）で階層へ分配。null packet を除去。最大 3 階層。OFDM フレーム
  同期は情報 byte の先頭へ 1 byte シフト。
- **Energy dispersal (§3.5、Ordinance Annexed Table 15):** PRBS 生成多項式 `g(x) = X^15 + X^14 + 1`。
  レジスタ初期値 `100101010000000`（左から昇順）。**OFDM フレームごとに初期化**。
  同期 byte を除く transmission TSP の全ビットへ bit 単位で XOR。同期 byte 中も
  シフトレジスタはシフトし続ける。
- **Delay adjustment (§3.6、Table 3-7):** byte interleaving の 11 TSP 遅延を補償。
  所定の `N`（その層のセグメント数）に対する `a·N-11` の TSP 数。例:
  DQPSK 1/2 は Mode 1/2/3 で `12N-11 / 24N-11 / 48N-11`。全層の送受信遅延が
  1 フレームに揃うよう選ぶ。
- **Byte interleaving (§3.7、Fig. 3-9):** 畳み込みバイトインターリーブ、深さ **12 byte**。
  path 0 は遅延なし、path i は `17·i` byte。1 byte ごとに path 0→1→…→11→0 と巡回。
  同期 byte の次の byte は無遅延の参照経路を通る。
- **Inner code (§3.8、Table 3-8):** 制約長 `k=7`、母符号レート `1/2` の
  **パンクチャド畳み込み符号**。生成多項式 `G1 = 171OCT`, `G2 = 133OCT`
  （64 状態）。パンクチャパターンはフレーム同期でリセット。

  | 符号化率 | X | Y | 送信系列 |
  | --- | --- | --- | --- |
  | 1/2 | `1` | `1` | X1, Y1 |
  | 2/3 | `10` | `11` | X1, Y1, Y2 |
  | 3/4 | `101` | `110` | X1, Y1, Y2, X3 |
  | 5/6 | `10101` | `11010` | X1, Y1, Y2, X3, Y4, X5 |
  | 7/8 | `1000101` | `1111010` | X1, Y1, Y2, Y3, Y4, X5, Y6, X7 |

- **Bit interleaving / mapping (§3.9):** S/P 後、ビットごとの遅延素子で
  インタリーブ。DQPSK/QPSK は 120 bit 遅延。16QAM は b1/b2/b3 に
  40/80/120 bit。64QAM は b1…b5 に 24/48/72/96/120 bit。
  - DQPSK は π/4 シフト。位相表（Table 3-10）: `00→π/4`, `01→-π/4`,
    `10→3π/4`, `11→-3π/4`。
  - 正規化（Table 3-11）: DQPSK/QPSK `Z/√2`、16QAM `Z/√10`、64QAM `Z/√42`
    （平均 OFDM シンボル電力が変調方式に依らず 1）。
  - データセグメントは Mode 1/2/3 で 96/192/384 キャリアシンボル（§3.9.5、Fig. 3-20）。
- **Combining hierarchical layers (§3.10):** `nc = 96/192/384`（Mode 1/2/3）、
  `Ns1 + Ns2 + Ns3 = 13`。
- **Time interleaving (§3.11.1、Fig. 3-23、Table 3-12):** セグメント内の
  キャリア i に `m_i = (i·5) mod 96` の畳み込み遅延をかけ、遅延量は
  インタリーブ長 `I` に対し `I·m_i` シンボル。`I` は層ごとに指定可。
  Table 3-2 の総遅延は Mode 1: `I=4 (380 symbols), I=8 (760), I=16 (1520)`、
  Mode 2: `I=2 (190), I=4 (380), I=8 (760)`、Mode 3: `I=1 (95), I=2 (190),
  I=4 (380)`（いずれも `I·95` に一致）。
  Table 3-12 は、この遅延をフレーム長の整数倍に揃えるための**送信側の遅延
  補正値**（シンボル数）と送受信フレーム数を与えます:

  | Mode 1 `I` | 補正 (sym) / frames | Mode 2 `I` | 補正 (sym) / frames | Mode 3 `I` | 補正 (sym) / frames |
  | --- | --- | --- | --- | --- | --- |
  | 0 | 0 / 0 | 0 | 0 / 0 | 0 | 0 / 0 |
  | 4 | 28 / 2 | 2 | 14 / 1 | 1 | 109 / 1 |
  | 8 | 56 / 4 | 4 | 28 / 2 | 2 | 14 / 1 |
  | 16 | 112 / 8 | 8 | 56 / 4 | 4 | 28 / 2 |

  遅延補正は time interleaving の**前**に施します（Table 3-12 注記）。
- **Frequency interleaving (§3.11.2):**
  - **部分受信セグメントには inter-segment interleaving をかけない**（§3.11.2
    [Description]。1 セグメント受信機を想定）。inter-segment は差動群・同期群の
    それぞれ内部で 2 セグメント以上に対して行う。
  - **Intra-segment** は 2 段: (1) セグメント番号 k によるキャリア回転
    （出力 i ← 入力 `(k+i) mod nc`。部分受信 No. 0 では `k=0` のため回転は恒等）、
    (2) Table 3-13 (a)/(b)/(c) のキャリアランダマイズ（Mode 1: 96 点、Mode 2: 192 点、
    Mode 3: 384 点の置換）。
- **OFDM frame structure / pilot signals (§3.12–3.13):**
  - 1 フレームは **204 OFDM シンボル**。
  - SP は BPSK。周波数方向に **12 キャリアごと**、時間方向に **4 シンボルごと**に挿入
    （挿入位置は `k mod 12 == 3·(symbol mod 4)`）。PRBS `g(x) = X^11 + X^9 + 1`、
    セグメントごとの初期値は Table 3-16。中央セグメント（No. 0）の初期値は
    Mode 1/2/3 で `11001000010 / 01110001001 / 00100001011`。
  - CP は同一キャリア位置の BPSK で全シンボル一定。
  - Wi と変調信号の対応（Table 3-17）: `Wi=1 → (-4/3, 0)`、`Wi=0 → (+4/3, 0)`。
  - 帯域右端に連続キャリア 1 本（モードにより位相固定、Table 3-19）。
  - CP/TMCC/AC キャリアのセグメント別配置は Table 3-14（差動）と
    Table 3-15（同期）。配置は周波数方向にランダム化。AC1 は差動/同期で同一位置、
    AC2 は差動のみ。
- **Transmission spectrum (§3.14):** セグメント No. 0 が全帯域の中心。OFDM
  セグメント番号は中心から上下交互。部分受信は常に No. 0。
- **Guard interval (§3.14.2、Fig. 3-33):** IFFT 出力の後半部分をそのまま先頭に付加
  （有効シンボルのコピー）。

### 4.5 受信チェーン（原典送信順序の逆順として導出、`[導出]`）

原典は**送信側**の方式を規定し、受信機の実装順序を明記した節はありません
（受信関連は §3.2.2 の「モデル受信機」と各節の [Description] のみ）。したがって
以下は送信順序（§4.4）の論理的な逆順と、§3.2.2.2 / Fig. 3-4 のモデル受信機が示す
「FFT → 復調 → 周波数/時間デインターリーブ → 階層分離 → デパンクチャ → Viterbi →
TS 再生」から導出したものです。**コードへの実装順序を規格が保証するものではなく、
実装時は fixture で確認します。**

```text
RTL-SDR raw IQ
  -> 周波数補正 (ppm / DC offset)
  -> 帯域抽出（中央 segment No. 0 = 428.571… kHz）
  -> リサンプル（FFT サンプリング 8.126984… MHz 相当へ）
  -> 同期（Mode / GI / フレーム同期を推定。CP 相関）
  -> FFT (Mode 1/2/3: 2048/4096/8192)
  -> 差動/同期復調 + 等化（同期変調は SP/CP でチャネル推定）
  -> 周波数デインターリーブ（intra-segment: ランダマイズ逆 → 回転逆。
       部分受信は inter-segment なし）
  -> 時間デインターリーブ（I·m_i の逆）
  -> ビットデインターリーブ（マッピング軟判定 + 遅延素子の逆）
  -> デパンクチャ（除外ビットを消去 0.0 で復元）
  -> Viterbi（inner、k=7 軟判定）
  -> バイトデインターリーブ（深さ 12、17·i byte の逆）
  -> エネルギー拡散除去（同じ PRBS で再度 XOR。同期 byte は除外）
  -> RS(204,188) 復号（outer、t=8）
  -> 188 byte TS パケット
  -> 単一 HTTP 有界 queue -> HTTP chunked 配信
```

- **順序の要点:** `RS(204,188) 復号`は `エネルギー拡散除去`の後、`エネルギー拡散
  除去`は`バイトデインターリーブ`の後に来ます（送信が
  `RS → energy dispersal → delay adjust → byte interleaving` の順のため）。
  デパンクチャは Viterbi の前（送信のパンクチャが内符号化の後）。
- **TMCC は分岐:** TMCC（§4.6）から層ごとの変調・符号化率・時間インターリーブ長・
  セグメント数を得ます。Mode/GI は同期段で推定します。
- **保持すべき設計上の注意:** この順序は `plans/実装計画.md` §6.1 の暫定案と一致します
  が、原典が受信順序として明記したものではないため、`[導出]` のままです。

### 4.6 TMCC（§3.15、`[本文確認]`）

- **キャリアビット割当（Table 3-20、204 bit）:**

  | ビット | 内容 |
  | --- | --- |
  | B0 | 差動復調の参照信号（Table 3-17 の `Wi`） |
  | B1–B16 | 同期信号 `w0 = 0011010111101110`、`w1 = 1100101000010001`（w0 の反転）。フレームごとに交互 |
  | B17–B19 | セグメント種別（差動 `111` / 同期 `000`） |
  | B20–B121 | TMCC 情報 **102 bit** |
  | B122–B203 | パリティビット（**82 bit**） |

- **TMCC 情報の割当（Table 3-22、102 bit 中 90 bit 定義・12 bit 予約）:**

  | ビット | 内容 | 備考 |
  | --- | --- | --- |
  | B20–B21 | システム識別 | `00`=地上デジタルテレビ、`01`=地上デジタル音声、他予約 |
  | B22–B25 | 伝送パラメータ切替インジケータ | 通常 `1111`、切替前 15 フレームからカウントダウン |
  | B26 | 起動制御信号（緊急警報放送開始フラグ） | `1`=起動制御あり |
  | B27 | 部分受信フラグ（現行） | `1`=部分受信あり |
  | B28–B40 | 現行 layer A 伝送パラメータ | 13 bit |
  | B41–B53 | 現行 layer B | 13 bit |
  | B54–B66 | 現行 layer C | 13 bit |
  | B67 | 部分受信フラグ（次） | |
  | B68–B80 | 次 layer A | 13 bit |
  | B81–B93 | 次 layer B | 13 bit |
  | B94–B106 | 次 layer C | 13 bit |
  | B107–B109 | 接続セグメント位相補正値 | 全 bit `1` |
  | B110–B121 | 予約 | 全 bit `1` |

- **伝送パラメータ情報の内訳（Table 3-23、13 bit）:** キャリア変調 3 bit +
  畳み込み符号化率 3 bit + 時間インターリーブ長 3 bit + セグメント数 4 bit。

  各 3 bit フィールドの符号（Table 3-28〜3-30）:

  | 値 | 変調 (T.3-28) | 符号化率 (T.3-29) | 時間 IL 長 I (T.3-30, Mode 1/2/3) |
  | --- | --- | --- | --- |
  | 000 | DQPSK | 1/2 | 0 / 0 / 0 |
  | 001 | QPSK | 2/3 | 4 / 2 / 1 |
  | 010 | 16QAM | 3/4 | 8 / 4 / 2 |
  | 011 | 64QAM | 5/6 | 16 / 8 / 4 |
  | 100 | 予約 | 7/8 | 未使用（ISDB-TSB 用） |
  | 101–110 | 予約 | 予約 | 予約 |
  | 111 | 未使用層 | 未使用層 | 未使用層 |

  セグメント数の 4 bit（Table 3-31）: `0000`=予約、`0001`–`1101`=1–13 セグメント、
  `1110`=予約、`1111`=未使用層。

  注: 未使用層（layer）は各フィールド `111`（セグメント数は `1111`）、
  次情報が無い場合も同じ値で埋めます（§3.15.6.5–3.15.6.8）。
- **TMCC の誤り訂正（§3.15.6.9）:** B20–B121 を difference-set cyclic code
  **(273,191)** の短縮符号 **(184,102)** で誤り訂正符号化。生成多項式:

  ```text
  g(x) = x^82 + x^77 + x^76 + x^71 + x^67 + x^66 + x^56 + x^52 + x^48
       + x^40 + x^36 + x^34 + x^24 + x^22 + x^18 + x^10 + x^4 + 1
  ```

- **TMCC の変調（§3.13.3、§3.15.6.10）:** DBPSK。参照 `B'0 = Wi`、
  `B'k = B'k-1 XOR Bk`。シンボル点は情報 `0 → (+4/3, 0)`、`1 → (-4/3, 0)`。
- 同一 TMCC は複数キャリアで送られるため、キャリア加算で低 C/N 化できます
  （§3.15.6.9 [Description]）。
